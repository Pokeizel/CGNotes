Scenes

Scenes are collections that include, at least, objects, observers, and scene parameters.
Objects are usually described by a mathematical model (points that make up a sphere, box, plane, cone, torus, polygon...), ideally with an implicit function. An object that can be described with boolean operations between primitive shapes is what's known as Constructive Solid Geometry.
Observers include the "eye" position and the projection pane.
There are countless scene parameter that affect how the scene is rendered, such as lighting, resolution, fog, materials, roughness, field of view, just to name a few...


Diagram of possible data structure for objects in a scene.

To implement a scene in somewhere like C, where rights regarding object orientation are nonexistent, we can create some abstractions freely by exploiting some legal loopholes.
We can use a linked list to store objects, but the data type the list will handle will be a "neutral" type. All shapes share some obligatory data, such as a shape and perhaps a color. They all should have a method to calculate intersections with them, but since these methods vary greatly between shapes, we can have a function pointer to some method that deals with that. Any additional data the shape needs to exist (for example, radius, depth, height...) can live in a "private data" field.
To decide which color is used for a pixel in the framebuffer, intersections with ALL objects in the scene and the ray cast from the eye need to be calculated at least once per pixel. This is of course very slow, and it's usually where most of the processing time is spent.
Some intersection calculations are not trivial (such as the torus's), and some are ad hoc methods, or "chancletazos".
